# react-native-turnstile-bridge

[Cloudflare Turnstile](https://developers.cloudflare.com/turnstile/) for React Native and Expo, on iOS, Android and the web.

Turnstile only exists as a JavaScript widget. On iOS and Android this package runs it inside [`react-native-webview`](https://github.com/react-native-webview/react-native-webview). On the web (react-native-web, Expo web) there is no WebView: the widget is rendered straight into your page. The API is the same everywhere, and there is no native code of its own, so it works in Expo Go, in Expo dev builds and in bare React Native apps.

What you get:

- `<Turnstile />`, the visible widget. It resizes itself when Turnstile changes size.
- `<TurnstileHeadless />`, for invisible site keys, with `controller.getToken()` to fetch a fresh token.
- `TurnstileController` to reset, remove, re-render, execute, reload or destroy the widget, plus its state and an event stream.
- Typed events for every Turnstile callback, as a union you can `switch` on.
- Error codes sorted into categories, with an `isRetryable` flag.
- Persistent cookies and storage, so returning users see fewer challenges.

You still have to check every token on your server with the [siteverify API](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/). A token on its own proves nothing.

## Installation

```bash
npm install react-native-turnstile-bridge react-native-webview
```

With Expo, install the WebView through Expo so you get the version that matches your SDK:

```bash
npx expo install react-native-webview
npm install react-native-turnstile-bridge
```

For the web, your app also needs `react-native-web` and `react-dom`, which Expo projects already have.

On Android release builds, check that `android.permission.INTERNET` is in your manifest. Expo and the React Native template add it for you.

## The `baseUrl` prop

Turnstile checks the hostname of the page that hosts it. On iOS and Android, that page is generated by the package and `baseUrl` decides which origin it gets. So:

1. In the Cloudflare dashboard, add a hostname to your widget, say `example.com`.
2. Pass `baseUrl="https://example.com"`.

Nothing is downloaded from that URL. It only sets the origin of the page. If the hostname isn't on the list, Turnstile fails with error `110200`.

On the web `baseUrl` is ignored, because the widget runs on your real site. Add your site's domain to the allowed hostnames instead, and if you send a Content Security Policy, allow `https://challenges.cloudflare.com` in `script-src` and `frame-src`.

While developing, Cloudflare's [test site keys](https://developers.cloudflare.com/turnstile/troubleshooting/testing/) accept any hostname:

| Site key | Behaviour |
| --- | --- |
| `1x00000000000000000000AA` | always passes, visible |
| `2x00000000000000000000AB` | always fails, visible |
| `1x00000000000000000000BB` | always passes, invisible |
| `2x00000000000000000000BB` | always fails, invisible |
| `3x00000000000000000000FF` | forces an interactive challenge |

## Usage

```tsx
import { Turnstile } from 'react-native-turnstile-bridge';

<Turnstile
  baseUrl="https://example.com"
  options={{ siteKey: '1x00000000000000000000AA', action: 'login' }}
  onToken={(token) => authApi.login({ captchaToken: token })}
  onError={(error) => console.warn('Turnstile failed', error.code)}
  onExpired={() => console.log('Token expired')}
/>;
```

`options` takes the [Turnstile render parameters](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/#configurations) in camelCase: `theme`, `size`, `language`, `appearance`, `execution`, `retry`, `retryIntervalMs`, `refreshExpired`, `refreshTimeout`, `feedbackEnabled`, `action` and `cData`.

### With a controller

```tsx
import { Turnstile, useTurnstileController, useTurnstileState } from 'react-native-turnstile-bridge';

function SignInForm() {
  const controller = useTurnstileController();
  const { status, token } = useTurnstileState(controller);

  return (
    <>
      <Turnstile controller={controller} baseUrl="https://example.com" options={{ siteKey: '...' }} />
      <Button title="Sign in" disabled={!token} onPress={() => submit(token)} />
    </>
  );
}

// Elsewhere:
const token = await controller.waitForToken({ timeoutMs: 60000 });

await controller.reset();    // new challenge in the same WebView
await controller.remove();   // take the widget off the page, keep the WebView
await controller.render();   // put it back after remove()
await controller.execute();  // start the challenge when execution is "execute"
await controller.reload();   // reload the whole page
await controller.destroy();  // free the WebView right away
controller.recreate();       // build a new one after destroy()
```

What you can read from it:

| Member | Meaning |
| --- | --- |
| `status` | `idle`, `loading`, `ready`, `interactive`, `verified`, `expired`, `timedOut`, `failed`, `unsupported`, `destroyed` or `disposed` |
| `token`, `hasToken` | the last valid token |
| `lastError` | the last `TurnstileError` |
| `addEventListener(listener)` | every event, returns an unsubscribe function |
| `subscribe` / `getState` | state changes, ready for `useSyncExternalStore` |
| `isAttached` | whether a widget is currently connected |

### Events

```ts
controller.addEventListener((event) => {
  switch (event.type) {
    case 'token':
      send(event.token);
      break;
    case 'failed':
      if (event.error.isRetryable) controller.reset();
      else showFatal(event.error);
      break;
    case 'expired':
    case 'timedOut':
      controller.reset();
      break;
    case 'interactionRequired':
      scrollToWidget();
      break;
  }
});
```

The other event types are `loaded`, `interactionCompleted`, `unsupported` and `resized`.

### Invisible keys

With an invisible site key there is nothing to show. `<TurnstileHeadless />` runs the widget in a hidden box and you ask the controller for tokens:

```tsx
const controller = useTurnstileController();

<TurnstileHeadless controller={controller} baseUrl="https://example.com" options={{ siteKey: '...' }} />;

try {
  const token = await controller.getToken(); // a new token on every call
  await api.submit(token);
} catch (error) {
  // error.error.code === 'interaction_required' means Cloudflare wants a
  // click: show a visible <Turnstile /> instead.
}
```

## Freeing the WebView

The WebView is released when `<Turnstile />` unmounts. You can also let go of it earlier: `controller.destroy()` removes the widget and unmounts the WebView, and the component renders nothing until `controller.recreate()`. On a one-time form, calling `destroy()` once you have the token gives the memory back.

Controllers from `useTurnstileController()` hold no native resource and need no cleanup. If you create one with `new TurnstileController()` outside React, call `dispose()` when you are done.

## Cookies and storage

Clearance only sticks if cookies and storage survive, so the WebView runs with DOM storage and the cache on, incognito off, third-party cookies allowed on Android (the Turnstile iframe comes from another origin) and the shared cookie store on iOS.

The package doesn't ship a way to clear them, because that needs a native module. [`@react-native-cookies/cookies`](https://github.com/react-native-cookies/cookies) can do it if you need a logout that wipes everything.

## Errors

A `TurnstileError` has the raw Turnstile `code`, a `category` and `isRetryable`.

| Category | Typical codes | Retry? | Usually means |
| --- | --- | --- | --- |
| `invalidConfiguration` | 110100, 110110, 110200, 110420, 110430, 400xxx | no | wrong site key, hostname not allowed (check `baseUrl`), bad `action` or `cData` |
| `unsupportedEnvironment` | 110500, 110510 | no | WebView not supported, or the user agent was changed |
| `initialization` | 100xxx, 105xxx, 200010 | no | Turnstile couldn't start |
| `clockSkew` | 200100 | no | the device clock is off |
| `challengeTimeout` | 11060x, 11062x | yes | the challenge or the interaction timed out |
| `challengeFailed` | 600xxx | yes | the challenge failed, possibly a bot |
| `clientExecution` | 102xxx to 106xxx, 120xxx, 300xxx | yes | generic client-side error |
| `network` | `script_load_failed`, `page_load_failed`, `load_timeout` | yes | no connection, or the Cloudflare domain is blocked |
| `bridge` | `not_attached`, `disposed`, `interaction_required`, ... | no | the package was used the wrong way |

Methods of the controller reject with a `TurnstileException`, whose `error` field is the `TurnstileError`.

## Checking the token on your server

Send the token to your backend and call siteverify with your secret key. The secret key never goes in the app.

```bash
curl -X POST https://challenges.cloudflare.com/turnstile/v0/siteverify \
  -d secret=YOUR_SECRET_KEY \
  -d response=TOKEN_FROM_THE_APP
```

A token can be used once, and it expires after 300 seconds.

## Replacing parts

Each piece below is an interface with a default implementation, passed as a prop:

| Interface | Default | Role |
| --- | --- | --- |
| `TurnstileEngine` | `WebViewTurnstileEngine` on iOS/Android, `WebTurnstileEngine` on the web | hosts the widget |
| `TurnstileDocumentBuilder` | `TurnstileHtmlDocumentBuilder` | writes the HTML page (and gives the script URL) |
| `TurnstileNavigationPolicy` | `DefaultTurnstileNavigationPolicy` | decides which navigations stay in the WebView |
| `TurnstileLinkHandler` | `SystemBrowserLinkHandler` | opens the privacy and terms links |
| `TurnstileSession` | one per engine | the connection the controller talks to (handy to fake in tests) |

Extra props for react-native-webview go through `webViewProps`.

## How the code is organised

| Folder in `src/` | Contents |
| --- | --- |
| `core/` | options, events, errors, status |
| `bridge/` | `TurnstileSession`, commands, message decoder |
| `html/` | the HTML/JS page used in the WebView |
| `controller/` | `TurnstileController` |
| `engine/` | `TurnstileEngine`, the react-native-webview engine and the web engine |
| `navigation/` | navigation policy and link handler |
| `components/` | `Turnstile`, `TurnstileHeadless` and the hooks |

The controller only knows about `TurnstileSession`, never about a WebView, which is why most of the package is tested with plain Jest and a fake session. The components only render `engine.Host`. The web engine is picked by the bundler through `defaultEngine.web.ts`, so react-native-webview is never bundled for the web. Both engines send the same JSON messages and use the same decoder.

## Troubleshooting

| Problem | What to do |
| --- | --- |
| Error `110200` | The `baseUrl` host isn't in the widget's allowed hostnames. |
| Error `110510` | Don't change the WebView user agent (`webViewProps.userAgent`). |
| `load_timeout` or `script_load_failed` | Check that `challenges.cloudflare.com` is reachable: VPN, firewall, missing `INTERNET` permission. |
| The widget ignores taps inside a ScrollView | Give it enough room and avoid nesting it in a horizontally scrolling view. |
| `getToken()` rejects with `interaction_required` | The key isn't invisible, or Cloudflare wants a click. Show a visible `<Turnstile />`. |
| Web: `load_timeout` after opening the page in a background tab | Browsers pause rendering in hidden tabs. The widget catches up once the tab is visible. `new TurnstileController({ loadTimeoutMs: null })` turns the timeout off. |
| Web: nothing shows up, CSP errors in the console | Allow `https://challenges.cloudflare.com` in `script-src` and `frame-src`. |
